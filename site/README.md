# openusd.dev

An independent Open USD developer reference built with Astro and the default Starlight theme.

## Edit content

- `src/content/docs/`: Markdown/MDX pages. A file’s path determines its URL. Guides live in `guides/`; add a purposeful guide to the explicit sidebar in `astro.config.mjs`. The shared Concepts page owns foundational definitions and stable fragment links.
- Standard Starlight frontmatter controls title, description, sidebar order, draft status, and page options.
- Guide frontmatter additionally records `reviewedAt`, `modifiedAt`, claim-level `sources`, and `related` guide IDs. MDX guides can use `GuideNotes`; Markdown guides keep claim-level citations, related task links and a dated review note in the body.
- `/start/` is the short task chooser. Its eight task guides have distinct goals; use the existing payment-events guide for shared retry and reconciliation logic. Provider details belong in the dedicated provider profiles, linked from the ecosystem directory, and foundational definitions belong in Concepts.
- A guide source can include its own `reviewedAt` when that page's claim was rechecked. This dates that specific review without refreshing untouched registry records or duplicating source URLs.
- `src/data/providers.json`: provider identities and sourced profile statements.
- `src/data/networks.json`: native OUSD deployments, exact contract/explorer links, and sourced setup/fee/operational profiles.
- `src/data/capabilities.json`: individual capabilities, access requirements and evidence.
- `src/data/sources.json`: authoritative URLs and actual review/publication dates.
- `src/data/updates.json`: dated ecosystem news and separately labelled site changes.
- Registry records drive the directory, provider comparisons, network reference and JSON export. Do not maintain separate copies.

## Theme and structure

The homepage uses Starlight’s built-in splash template and hero actions. All other content keeps the default documentation layout.

Starlight owns navigation, responsive page layouts, typography, light/dark mode, table of contents, search, code blocks and metadata. Keep its defaults. `astro.config.mjs` contains navigation and the canonical site URL. `src/styles/directory.css` only arranges domain-specific registry controls and records.

`src/pages/providers/[id].astro` uses the official `StarlightPage` component through a thin layout wrapper. All editorial pages, including the directory and networks reference, use the standard docs collection. Registry components are embedded in MDX and inherit the framework sidebar. Small Astro components handle data-driven evidence, dataset downloads and copy buttons inside MDX.

Starlight builds Pagefind search and the standard Astro sitemap integration generates `sitemap-index.xml` and `sitemap-0.xml`. The original `/sitemap.xml` remains a compatibility index. `/search` remains a page explaining the built-in search shortcut. JSON exports, search, the retired guide index, retired status and 404 pages are excluded from the sitemap. Provider record IDs and existing network directory anchors remain stable. `/data/ecosystem.json` is the single current dataset; `/data/ecosystem.schema.json` describes its structure. The dataset is 0.1 alpha (`schemaVersion: "0.1.0-alpha"`), defined once by `DATASET_VERSION` in `src/lib/schema.ts`. Schema and TypeScript types derive from the current Zod definitions; there is no parallel versioned export. The fetch-and-query example on `/data/` is executed by the test suite.

The current static host ignores `_redirects`: `/status/` and the retired `/guides/` index have noindex, canonicalized, immediate HTML redirect fallbacks. The latter points to `/guides/what-is-open-usd/` and is excluded from Pagefind. A server 301 and default Python HTTP-client access still need hosting support. Generated-host pages canonicalize to `openusd.dev`.

## Review and checks

Run `npm run validate`, `npm run check`, `npm run build`, `npm test`, `npm run check:links`, and `npm run check:seo`. Preview with `npm run preview`. Check search, directory filters, provider profile links, copy buttons and mobile navigation after UI changes.

Both build modes include a fast, offline generated-link check to prevent redirecting internal navigation. Run `npm run check:navigation` to repeat it without rebuilding. See `docs/performance.md` for cache-safety rules, the current hosting limitation, and targeted release checks; expensive browser/network audits stay outside routine builds.

## Agent-readable documentation

`/llms.txt` is a curated index generated by `src/pages/llms.txt.ts` from page metadata, handbook task definitions, and provider/network records. It identifies Open Standard's OUSD, groups the documentation by reader task, and links both Markdown and original pages. The existing JSON dataset and schema are linked, never copied into a second registry.

The pinned `astro-aeo` integration generates individual `.md` companions and `/llms-full.txt` from the finished HTML, including custom provider/network routes and rendered MDX components. Its scope is limited to those exports and Markdown discovery links. It does not manage this site's robots, sitemap, schema, analytics, or metadata. No client-side runtime is added. `includeLastModified` is disabled so build/Git times cannot appear as new source-review dates.

Exports retain code, tables, citations, eligibility restrictions, and review/testing notes. Navigation, forms, heading-link controls, and the analytics-consent interface are excluded. Internal links retain canonical HTML destinations and their exact fragments; Markdown does not duplicate HTML's custom heading IDs or legacy anchor aliases. Each companion records its original URL in frontmatter. A deliberate preview build omits the companions and labels its index as disabled.

`npm run build` runs `check:agents` after generation. This fails the build for missing page coverage, broken fragment destinations, lost substantive links, altered code blocks, missing token addresses, or dropped review/testing caveats. When adding an editorial page, assign it an index section and rerun the checks. `llms.txt` is a voluntary discovery convention; availability does not establish crawler adoption, ranking, or model use.

Content dates are editorial facts, not build timestamps. The migration preserves the existing registry data and review dates. No integration is independently tested unless supported by a real recorded test artifact.

## Publishing and indexing

Sites identity and static output are in `.openai/hosting.json`. Publish through the Sites source/build workflow. Preserve the current public audience and canonical origin `https://openusd.dev`.

The owner authorized the public search launch on October 10, 2026. `npm run build` explicitly enables production indexing; `npm run build:preview` explicitly disables it. `npm run check:seo -- --preview` verifies a preview build. Public hosting and search-engine indexing are separate settings. Follow `AGENTS.md` for editorial review requirements. No analytics or scheduled source monitoring is enabled.

## UI boundaries

Use default Starlight components for the header, sidebar, mobile menu, appearance selector, pagination, and search. Do not install a navigation/theme replacement. Small component overrides retain the default header and sidebar while placing the built-in appearance selector at the sidebar bottom on desktop. The mobile menu keeps its default selector; splash pages without a sidebar keep the header selector. The footer retains the default footer and adds site links. shadcn Input and Native Select are server-rendered inside DirectoryFilters; they add no hydrated React runtime. Tailwind utilities are loaded without preflight to avoid resetting Starlight. Domain CSS must not target the framework header, sidebar, or menu.
